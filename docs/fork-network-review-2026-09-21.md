# Fork network review — 2026-09-21

Follow-up: selected candidates were subsequently integrated; see [integration decisions and validation](fork-integration-2026-09-21.md). The review below records the pre-integration assessment.

Review baseline: `lofcz/docxjs@667e240d1ed0dfcd0e938894ac3e29433c678c52`, including selective integration `b63a4937a26bc089117c71b9384f2c1f4988c4a0`. This is a source review and prioritization, not an integration or runtime validation of the candidates.

## Coverage and method

- GitHub reported 286 forks; its paginated forks endpoint returned 278 visible repositories. Compared their default branches to upstream baseline `191d3e0`. 55 had ahead commits, including our fork; two comparisons returned 404 (`SAY-5/docxjs`, `richard702ayu/docxjs`). Ahead counts alone do not establish a new feature: several forks contain changes already implemented differently upstream.
- Enumerated 516 branches across the accessible repositories and compared 101 non-default branches to their respective default branches. Excluded conventional `elements`, `next`, and `gh-pages` branches from this second comparison, and excluded our own branches. This is not an exhaustive review of every historical branch or detached descendant.
- Inspected commit lists and selected source diffs, then checked proposed fixes against our actual source and the earlier PR review. Large comparisons can omit patches; fetched individual commits for the shortlisted loadfix, klarso, fcapurso and DmitrySharabin changes.
- Also inspected the README and recent history of detached descendant `recon-vcs/docx-renderer`. Its own accuracy figures are not independently validated here.
- No runtime source, dependency, or distribution changes were made during this review. No candidate was merged or tested in our browser suite.

The prior review records **17 integrations/partial integrations and four fully deferred PRs**: #226, #204, #189 and #65. Partial omissions are separately documented there.

## Larger forks to mine, not merge wholesale

- **[klarso-gmbh, `klarso/preview-patches`](https://github.com/klarso-gmbh/docxjs/tree/098a8574ead4c132c3bfef7d586651cbe0f8d481):** 48 commits beyond its default branch, including measured pagination, repeat table headers, split rows, keep-next, anchored frames, border spacing and field evaluation. Best source for targeted layout follow-up. Several features are designed for an external paginating consumer, and overlap our adapted PRs.
- **[leonaves, `lokalise/patched-0.4.0`](https://github.com/leonaves/docxjs/tree/ed2eadd523f64f13f28ca54659db92680bedfce7):** richer drawing anchor metadata, VML groups, DrawingML group/shape parsing and floating-table anchors. Potential foundation for revisiting deferred drawing placement. Source inspection of the commit inventory is not evidence that its entire renderer behavior is safe to adopt.
- **[DmitrySharabin, `dist-with-fixes`](https://github.com/DmitrySharabin/docxjs/tree/3d7c2932659fcef89b6a2bb96c2ec960ad5e72c8):** linked textbox flow and column-relative anchors. Linked flow uses DOM geometry/ranges and moves content; evaluate text, images, tables, zoom and malformed chains. Its prebuilt bundle also contains changes we explicitly rejected earlier.
- **[gety-ai](https://github.com/gety-ai/docxjs/tree/95cf110c3d81ce08fff89d3063f77b88298a8497):** worker parsing, snapshot APIs, virtual page scrolling, image callbacks and a benchmark harness. Potentially useful for large Sciobot attachments. This is an API/lifecycle project: printing, browser find, selection, unmount cleanup and worker bundling need evaluation. No speedup was measured in this review.
- **[inj-src](https://github.com/inj-src/docxjs):** DrawingML shapes, groups, geometry/arc handling and textbox alignment, with four added drawing documents. Useful reference for unsupported shapes; old renderer integration and missing automated expected-output evidence make a wholesale import unattractive.
- **[loadfix](https://github.com/loadfix/docxjs):** extensive comments/revisions, fields, shapes, charts, pagination and conformance work. Mine isolated fixes. Its security patch and later feature waves are broad behavior changes; the existence of a large test corpus is not proof of compatibility with our current suite.
- **[apollocmh](https://github.com/apollocmh/docx-preview):** pagination/font work followed by a monorepo architecture rewrite, framework viewers and encrypted DOCX support. Consider as a separate comparative prototype, not a small patch source.
- **[millet0328/docx-preview-sync](https://github.com/millet0328/docx-preview-sync)** and detached **[recon-vcs/docx-renderer](https://github.com/recon-vcs/docx-renderer):** substantial layout-engine alternatives. Recon's reported visual accuracy uses a particular five-page fixture and pixel mismatch scoring; do not treat that as general Word fidelity or a validated advantage over our fork.
- **[falconlaw-ai, `main`](https://github.com/falconlaw-ai/docjs/tree/2ce2f7736d975e6cfd82a67de59330be2086508f)** and **[paulmeller](https://github.com/paulmeller/docxjs):** review/comment UI, React preview lifecycle, zoom and annotations. Lower priority for our current plain attachment preview, but relevant if interactive document review becomes a product requirement.

## Duplicates and changes not recommended as-is

- **i-davydov's shared-abstract-numbering fix:** initially promising, but our current `parseNumberingFile` already clones levels for each concrete `numId`. No new patch needed. flowkscai's older mapping workaround is weaker than our existing implementation.
- **NEOLPAR bidi cleanup:** removes duplicate switch cases; actual bidi support is already in our source. No new rendering capability.
- **loadfix cnfStyle crash guard:** our parser already handles missing packed `val` and reads named flags. No new fix needed.
- **dmschreiber nil/none borders and hidden rows:** existing upstream baseline already handles these; its broad formatting diff obscures that overlap.
- **flowkscai image cropping, historical small-caps/RTL/smart-tag/type-export branches:** existing implementations already cover the core feature. Old fork ancestry does not imply missing functionality.
- **getmetal page-break numbering, kingandrewsolomon fragments, tracked-change metadata forks and the reviewed PR branches:** already covered by b63a493 or its explicit deferrals. Keep our adapted versions.
- **kasialorek numbering-from-zero patch:** suppresses `%1` outright. That would remove valid top-level numbering rather than fix the counter model.
- **Questra hyperlink sanitizer:** do not replace our current allowlist with its scheme-regex/relative-path fallback; ours explicitly addresses encoded control-character schemes.
- **fefeding color branch:** extract only the color normalization idea; do not import widespread `@ts-nocheck`, empty-paragraph injection or drawing-layout changes.
- **Luo SECTIONPAGES and naive page-number replacements:** page-group counts are not sufficient to implement section page numbering faithfully.
- **ZhenchongLi missing-section/margin defaults:** worth a separate malformed/minimal-document review, but avoid introducing hard-coded Word defaults without resolving section inheritance and explicit zero margins.

## Validation needed for an integration

Run our existing TypeScript/build/browser suite after each small batch and add focused tests that fail on the baseline. For layout changes, include actual geometry or Word-reference visual fixtures, not just HTML snapshots. Keep source attribution and rebuild distributions locally; do not copy fork bundles.
